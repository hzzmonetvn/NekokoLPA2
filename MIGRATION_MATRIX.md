# Rust migration matrix

Audit baseline: 2026-11-05, branch snapshot `b6f644a`. This is a static source audit, not a device/runtime parity certification. The six audit streams reported 40 capability rows; several rows group multiple files and some are subsystem-level rather than file-level. Do not interpret row count as audited-file count. `rust_unused_by_runtime` means no live app caller was identified in the inspected source, not proof that dynamic/reflection callers cannot exist.

Status vocabulary:

- `ported_live`: this capability's Rust implementation is called from an active application path (source-traced; not necessarily exercised on hardware).
- `rust_unused_by_runtime`: Rust/FRB code exists, but no active application caller was found.
- `partial_or_non_equivalent`: split, incomplete, or not proven behavior-equivalent/runtime-connected.
- `not_ported`: no Rust implementation identified; entry was dormant or out of current Android runtime.
- `platform_or_presentation_required`: the Android API, hardware, browser API, Flutter UI, or lifecycle boundary must remain at that layer.

## Audit limitations

- This matrix aggregates preliminary reports from six independent read-only source audits. It is a migration baseline, not the requested exhaustive per-file/per-symbol dependency graph.
- The aggregate contains 40 report entries, including grouped and broad rows; some reviewers did not establish exact callers or semantic parity. Those uncertainties are recorded above instead of promoted to completion.
- No device sessions, Android builds, Flutter tests, or hardware/eUICC operations were performed as part of this audit. Prior verification in `PORTING.md` applies only to its recorded change set and commands.
- The migration remains incomplete. In particular, active RSP/ES9, TS.43, notification, signing, profile/database/settings, and reader orchestration flows still contain Dart implementations or unconnected Rust APIs.
